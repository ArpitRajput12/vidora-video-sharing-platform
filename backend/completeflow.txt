## Your Approach — Step by Step

---

### Phase 1 — Before Writing Any Code

For EVERY controller file, do this first:

```
Open a blank paper or notion page
      ↓
Write in plain english what each function does
      ↓
Write the flow (like we did together)
      ↓
Identify what's coming in (req.body/params/query/user)
      ↓
Identify edge cases
      ↓
THEN open VS Code
```

Never open VS Code first. Think first, code second.

---

### Phase 2 — Order to Attempt Controllers

Don't do them randomly. Do them in this order — easiest to hardest:

```
1. healthcheck.controller.js   → literally 3 lines
2. user.controller.js          → already done mostly
3. tweet.controller.js         → simple CRUD
4. subscription.controller.js  → concepts already understood
5. like.controller.js          → similar to subscription
6. comment.controller.js       → CRUD + aggregation
7. playlist.controller.js      → CRUD + relationships
8. video.controller.js         → most complex
9. dashboard.controller.js     → pure aggregation
```

Each one builds on the previous. Don't jump to video before tweet.


---

### Phase 3 — For Each Controller, Ask 5 Questions

```
1. What does this function do? (plain english)
2. What URL hits it?
3. Where is data coming from?
4. What can go wrong? (edge cases)
5. What goes back to frontend?
```

You already know this framework. Use it every single time.

---

### Phase 4 — When You're Stuck

Follow this order:

```
Stuck?
      ↓
Re-read the model first
      ↓
Think about the flow on paper
      ↓
Check MongoDB/Mongoose docs
      ↓
Ask me — share your attempt, not just the problem
```

Never ask me without trying first. Always share what you attempted. That's where real learning happens.
